## 1. نظرة عامة على النظام | System Overview

### 1.1 الهدف من المنصة
**منصة نبيه** هي نظام متكامل لتحسين التوثيق السريري (CDI - Clinical Documentation Improvement) يعتمد على الذكاء الاصطناعي لمساعدة فرق الترميز الطبي في:
- تحليل الملاحظات السريرية وتحديد التشخيصات
- اقتراح أكواد ICD-10-CM الصحيحة
- إنشاء استفسارات للأطباء لتحسين التوثيق
- حساب الأثر المالي لتغييرات DRG

### 1.2 الجمهور المستهدف
- أخصائيو تحسين التوثيق السريري (CDI Specialists)
- فرق الترميز الطبي
- مدراء إدارات المالية والجودة في المستشفيات
- المشرفون على برامج CDI

## 3. الميزات الرئيسية | Key Features

### 3.1 تحليل الملاحظات السريرية بالذكاء الاصطناعي
- **التشخيص الرئيسي**: تحديد السبب الأساسي للدخول
- **التشخيصات الثانوية**: الحالات المصاحبة الموثقة
- **التشخيصات المستنتجة**: حالات مستدلة من البيانات السريرية
- **أكواد ICD-10-CM**: اقتراح الأكواد الصحيحة والكاملة

### 3.2 استفسارات الأطباء
- توليد استفسارات مهنية للأطباء
- تضمين السياق السريري والنتائج المخبرية
- صياغة متوافقة مع معايير CDI

### 3.3 الدردشة التفاعلية
- مناقشة التشخيصات مع الذكاء الاصطناعي
- الحصول على توضيحات حول أكواد ICD-10
- استشارة فورية حول التوثيق

### 3.4 تحليل الأثر المالي (DRG)
- حساب الفرق بين DRG القديم والجديد
- تقارير مفصلة حسب المستشفى والقسم
- تجميع الوفورات/الخسائر حسب الأخصائي

### 3.5 التقارير والتصدير
- تقارير PDF احترافية
- تصدير Excel للتحليل
- إحصائيات الأداء

## 4. نظام الأمان | Security System

### 4.1 المصادقة متعددة العوامل (MFA)
- إرسال رمز OTP عبر البريد الإلكتروني
- صلاحية الرمز 30 دقيقة
- قفل الحساب بعد 5 محاولات فاشلة

### 4.2 التشفير والحماية
- تشفير كلمات المرور باستخدام bcrypt
- JWT للجلسات مع انتهاء صلاحية 7 أيام
- حماية HTTPS مع شهادة SSL

### 4.3 سجلات التدقيق
- تسجيل جميع عمليات تسجيل الدخول
- تتبع التحليلات والتعديلات
- تنبيهات أمنية عبر البريد الإلكتروني

## 5. آلية العمل | How It Works

### 5.1 دورة عمل التحليل

```
1. إدخال الملاحظة السريرية
       ↓
2. إرسال للتحليل بالذكاء الاصطناعي (Ollama/Qwen2.5:32b)
       ↓
3. معالجة محلية على GPU (30-90 ثانية)
       ↓
4. استخراج التشخيصات وأكواد ICD-10
       ↓
5. توليد استفسارات الأطباء
       ↓
6. عرض النتائج للمستخدم
       ↓
7. إمكانية الدردشة للاستفسار
       ↓
8. تصدير التقارير (PDF/Excel)
```

### 5.2 معالجة البيانات
- **كل البيانات تُعالج محلياً** على الخادم
- لا يتم إرسال أي بيانات طبية لخوادم خارجية
- الذكاء الاصطناعي يعمل بدون اتصال بالإنترنت

## 6. إدارة الخدمات | Service Management

### 6.1 بدء تشغيل النظام

```bash
# تشغيل جميع الخدمات
sudo /app/start_nabih.sh
```

هذا السكريبت يقوم بـ:
1. تشغيل MongoDB (قاعدة البيانات)
2. تشغيل Ollama (خدمة AI)
3. تحميل نماذج الذكاء الاصطناعي في الذاكرة
4. تشغيل الخادم الخلفي (nabeeh_api)
5. تشغيل Nginx (خادم الويب)

### 6.2 إيقاف النظام

```bash
# إيقاف جميع الخدمات
sudo /app/stop_nabih.sh
```

### 6.3 مراقبة السجلات

```bash
# مراقبة سجلات الخادم الخلفي
sudo journalctl -u nabeeh_api -f

# مراقبة سجلات Nginx
sudo tail -f /var/log/nginx/access.log
```

## 8. الدعم والصيانة | Support & Maintenance

### 8.1 المهام الدورية

| المهمة | التكرار | الوصف |
|--------|---------|-------|
| نسخ احتياطي | يومي | نسخ قاعدة البيانات |
| تحديث النظام | شهري | تحديثات الأمان |
| مراجعة السجلات | أسبوعي | فحص الأخطاء |

### 8.2 استكشاف الأخطاء

**مشكلة: التحليل بطيء جداً**
- تأكد من تشغيل Ollama: `sudo systemctl status ollama`
- تحقق من ذاكرة GPU: `nvidia-smi`
- أعد تشغيل الخدمة: `sudo systemctl restart nabeeh_api`

**مشكلة: خطأ في تسجيل الدخول**
- تحقق من إعدادات SMTP للبريد
- راجع سجلات الأخطاء: `journalctl -u nabeeh_api`

### 8.3 ما يمكن تقديمه كدعم

1. **الدعم الفني**
   - تحديثات الأمان والصيانة الدورية
   - إصلاح الأخطاء البرمجية
   - تحسين أداء النظام

2. **التدريب**
   - تدريب المستخدمين الجدد
   - ورش عمل لفرق CDI
   - دليل استخدام مفصل

3. **التطوير المستقبلي**
   - إضافة ميزات جديدة
   - تكامل مع أنظمة أخرى
   - تحسين نماذج الذكاء الاصطناعي

4. **الاستشارات**
   - تحليل احتياجات CDI
   - اقتراحات التحسين
   - تقارير الأداء الدورية
